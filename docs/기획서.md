# RANDOM SHELF 기능 기획서

작성일: 2026-10-21

## 1. 개요

RANDOM SHELF는 표지가 가로로 늘어선 룰렛을 돌려 책 한 권을 무작위로 뽑아 주는 비회원 웹 서비스다. 이용자는 필터를 하나 고르고 `책 한 권 뽑기`를 누른다. 룰렛이 멈추면 가운데 선에 걸린 책의 상세 정보가 모달로 열리고, 이용자는 도서관이나 서점에서 그 책을 검색할 수 있다.

이 프로젝트는 외부 API로 책 추천 경험을 만드는 학습 과제다. 화면의 색상, 글꼴, 간격, 컴포넌트 수치는 `DESIGN.md`가 정한다. 이 문서는 기능과 데이터 규칙을 다룬다. API 조사와 표본 분석 결과는 자료조사 메모에 따로 둔다.

## 2. 범위

| 구분 | 내용 |
| --- | --- |
| 포함 | 메인 단일 화면, 단일 선택 필터, 가로 책 룰렛, 선정 책 상세 모달, 도서관·서점 검색 링크, 로딩·빈 결과·오류 상태 |
| 제외 | 회원가입·로그인, 데이터 생성·수정·삭제, 서비스 자체 DB, 쪽수 기반 필터, 예상 독서기간, ISBN 표시, 사서추천 원문 페이지 링크 |

서비스는 조회만 한다. 이용자가 고른 필터는 현재 화면에서만 유지하고 저장하지 않는다.

## 3. 화면 구성

화면은 메인 화면(`/`) 하나다. 책이 선정되면 화면을 이동하지 않고 중앙에 상세 모달을 연다.

| 영역 | 내용 |
| --- | --- |
| 헤더 | 좌상단 `RANDOM SHELF` 로고만 둔다. |
| 대표 문구 | 제목 `우연히 만나는 한 권의 책`, 설명 `오늘은 어떤 책을 만나게 될까요?` |
| 필터 | 단일 선택 칩 4개. 기본 선택은 `아무거나`다. |
| 룰렛 | 후보 책의 표지를 가로로 늘어놓고 가운데 선택선을 표시한다. |
| 메인 버튼 | `책 한 권 뽑기` |
| 상세 모달 | 선정 책의 정보, `다른 책 만나기`, `도서관 검색`, `서점 검색`, 닫기 |

## 4. 사용자 흐름

1. 이용자가 메인 화면에 들어오면 후보 책을 불러오는 동안 룰렛 자리에 정적 스켈레톤이 보인다.
2. 이용자가 필터 칩 하나를 고른다. 고르지 않으면 `아무거나`가 적용된다.
3. 이용자가 `책 한 권 뽑기`를 누르면 룰렛이 돈다.
4. 룰렛이 멈추면 가운데 선에 걸린 책의 상세 모달이 바로 열린다.
5. 모달에서 이용자는 다음 중 하나를 한다.
   - `도서관 검색` 또는 `서점 검색`으로 그 책을 외부 사이트에서 찾는다.
   - `다른 책 만나기`를 누른다. 모달이 닫히고 같은 필터로 룰렛이 다시 돈다.
   - 모달을 닫는다. 초점이 원래 버튼으로 돌아가고 메인 화면에서 다시 뽑을 수 있다.

## 5. 필터

필터 칩은 하나만 고를 수 있다. 각 필터는 한국십진분류(KDC) 대분류로 후보를 나눈다.

| 칩 라벨 | 후보에 넣는 KDC 대분류 | 설명 문구 |
| --- | --- | --- |
| `아무거나` | 모든 후보 | `분야 상관없이 모든 책에서 뽑아요` |
| `이야기와 문장` | 800 문학 | `소설, 시, 에세이 같은 문학 중에서 뽑아요` |
| `세상과 사람` | 100 철학, 200 종교, 300 사회과학, 900 역사 | `철학, 종교, 사회, 역사 책 중에서 뽑아요` |
| `과학과 기술` | 400 자연과학, 500 기술과학 | `자연과학과 기술·의학·공학 책 중에서 뽑아요` |

칩 줄 아래에는 지금 고른 칩의 설명 문구 한 줄을 보여 준다.

- 000 총류, 600 예술, 700 언어 분류의 책은 세 주제 필터에 들지 않고 `아무거나`에서만 뽑힌다.
- KDC를 찾지 못한 책은 추측해서 주제 필터에 넣지 않는다. 표지와 기본 정보가 유효하면 `아무거나` 후보로 둔다.

## 6. 책 뽑기 규칙

API에는 분류로 걸러 받는 요청 변수가 없다. 그래서 책 목록을 받은 뒤 앱에서 KDC를 추출하고, 고른 필터에 맞는 책만 후보로 남긴다.

### 6.1 후보 구성

1. 화면을 열면 중계 함수에서 책 100권을 받는다. 중계 함수는 `totalCount`로 페이지 수를 계산해 `numOfRows=100`의 페이지 하나를 무작위로 고른다. 고른 페이지가 100권보다 적은 마지막 페이지면 1페이지 앞부분으로 나머지를 채운다.
2. 받은 100권 가운데 서지정보 분리에 실패한 책, 표지 URL이 없거나 표지 이미지를 불러오지 못한 책을 뺀다. 대체 표지는 만들지 않는다.
3. 남은 책 중 고른 필터에 맞는 책을 후보로 삼는다.
4. 후보에서 무작위로 최대 20권을 골라 룰렛에 올린다. 후보가 20권보다 적으면 같은 책을 반복해 룰렛을 채운다.
5. 후보가 1권이라도 있으면 룰렛을 돌릴 수 있다. 후보가 0권이면 빈 결과 상태로 바꾼다.

필터를 바꾸거나 `다른 책 만나기`를 누르면 이미 받은 100권에서 후보를 다시 고른다. 재뽑기 때 직전에 뽑힌 책을 후보에서 빼지 않는다.

### 6.2 룰렛 동작

- 룰렛은 매번 빠르게 시작해 점점 느려지며 2200ms 동안 움직인다.
- 멈춘 시점에 가운데 선에 걸린 책을 선정한다. 화면에서 가운데에 보이는 책과 데이터상 선정한 책은 반드시 같아야 한다.
- 룰렛이 도는 동안 버튼을 다시 눌러도 새로 돌지 않는다.
- `prefers-reduced-motion: reduce` 환경에서는 룰렛과 모달의 움직임을 줄이거나 생략한다. 이때도 책 선정과 상세 확인은 할 수 있어야 한다.

## 7. 상세 모달

모달에는 아래 항목만 표시한다.

| 항목 | 데이터 출처 |
| --- | --- |
| 표지 | `referenceIdentifier` |
| 제목 | `title` |
| 저자 | `description` 앞부분의 서지정보 |
| 출판사 | `description` 앞부분의 서지정보 |
| 출판연도 | `description` 앞부분의 서지정보 |
| 사서의 추천 글 | `description`에서 서지정보를 떼어 낸 추천 글 |

- `DESIGN.md`의 "책 소개" 자리에 사서의 추천 글을 표시한다. 화면 라벨은 `사서의 추천 글`이다.
- 추천 글이 길면 모달 안에서 스크롤해 읽는다.
- `creator` 필드는 실제 저자가 아니라 `누리집` 같은 값이 들어 있어 저자 표시에 쓰지 않는다.
- `다른 책 만나기`는 모달 안에 둔다.

### 7.1 외부 링크

외부 링크는 아래 두 개다. API의 `url` 필드가 가리키는 사서추천 원문 페이지로는 이동하지 않는다.

| 버튼 | 대상 | URL |
| --- | --- | --- |
| `도서관 검색`(Primary) | 도서관 정보나루 | `https://www.data4library.kr/srch?srchText={제목}` |
| `서점 검색`(Secondary) | 교보문고 | `https://search.kyobobook.co.kr/search?keyword={제목}` |

- 검색어는 책 제목만 쓰고 URL 인코딩한다.
- 링크는 새 탭으로 연다.
- 두 URL은 2026-10-21에 제목 `채식주의자`로 요청해 검색 결과 페이지가 열리는 것을 확인했다.

## 9. 데이터 연동

### 9.1 API

| 항목 | 내용 |
| --- | --- |
| API | [문화공공데이터광장 국립세종도서관 사서추천도서](https://www.culture.go.kr/data/openapi/openapiView.do?id=362) |
| 요청 URL | `https://api.kcisa.kr/openapi/service/rest/meta13/getNLSF0401` |
| 요청 변수 | `serviceKey`(필수), `numOfRows`, `pageNo` |
| 인증 | 이미 발급받은 API 키를 쓴다. |
| 호출 한도 | 이 서비스의 사용량에는 충분하다. |

API 키는 브라우저 코드, 응답, 로그에 노출하지 않는다. 브라우저는 Netlify Functions로 만든 중계 함수를 부르고, 중계 함수가 환경변수의 키로 API를 부른다.

API 응답은 중계 함수와 브라우저 어디에도 캐시하거나 저장하지 않는다. 화면을 열 때마다 새로 받고, 받은 100권은 그 화면이 열려 있는 동안만 메모리에서 쓴다.

### 9.2 데이터 처리 규칙

- KDC는 `subjectCategory`에서 가져오지 않는다. 이 필드에는 KDC가 아니라 `추천도서` 같은 값이 들어 있고 비어 있는 경우도 있다.
- KDC는 `description`을 `사서의 추천 글` 앞에서 자른 서지정보 구간에서, 처음 나오는 `세 자리 숫자[.소수]-연도-번호` 형태의 청구기호로 추출한다. `description` 뒤쪽 `함께 읽으면 좋은 책`에 나오는 다른 책의 청구기호는 쓰지 않는다.
- `subjectKeyword`와 `extent`는 비어 있을 수 있으므로 필터나 화면 표시에 쓰지 않는다.
- 저자, 출판사, 출판연도는 `description`의 서지정보 구간에서 정규식으로 나눈다. 분리 규칙은 `자료조사.md` 3.3을 따른다. 정규식으로 나누지 못한 책은 뽑기 데이터에서 뺀다.
- 추천 글 뒤에 붙은 `함께 읽으면 좋은 책`과 그 이후 내용은 다른 책 목록이므로 표시하지 않는다. `함께 읽으면 좋을 책`처럼 문구가 다르거나, 문구 없이 마지막 인용 쪽수 `(N쪽)` 뒤에 다른 책의 청구기호가 이어지는 경우도 그 지점에서 자른다.
- 추천 글 표시는 `사서의 추천 글`, `사서의 추천글`, `사서의 추천`처럼 다를 수 있다. 청구기호 앞에 `아`가 붙은 어린이·청소년 자료도 KDC를 추출한다.
- `referenceIdentifier`의 표지 URL에 들어 있는 역슬래시(`http\://`)를 제거하고 `https://`로 바꿔 쓴다. 표지가 HTTPS로 열린다고 가정하며, 열리지 않는 책은 6.1의 규칙대로 후보에서 뺀다.

## 11. 단계별 구현 계획

1. 연동 검증: 발급받은 키로 정상 응답, 응답 형식, 페이지 이동, `totalCount`를 확인한다. 10장의 항목을 확인하고, 필터별 후보 수와 KDC 추출률을 본다.
2. 결과 반영: 연동 검증 결과를 이 문서와 `자료조사.md`에 반영한다.
3. MVP 개발: 메인 화면, 필터, 룰렛, 상세 모달, 상태 화면, 응답 정규화, 키 보호 구조를 구현한다.
4. 출시 점검: 모바일 사용성, 외부 링크, 키 노출 여부, API 사용량을 확인한 뒤 공개한다.
